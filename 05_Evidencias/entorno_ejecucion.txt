NOTA SOBRE LA RUTA DE EJECUCION
==============================================================================
Las pruebas de los modulos Java se ejecutaron sobre una copia del proyecto en una
ruta sin caracteres acentuados:

  C:\Users\jucanet\AppData\Local\Temp\pa_ev\

Motivo: en Windows, cuando la ruta del proyecto contiene caracteres no ASCII (la
"O" acentuada de "PROGRAMACION"), Gradle escribe el classpath del worker de
pruebas en un argfile codificado en UTF-8, pero el lanzador de Java lo interpreta
con la codepage ANSI del sistema. La ruta se corrompe, la entrada
build/classes/java/test se cae del classpath y ninguna clase de prueba se
encuentra (ClassNotFoundException en las 9 clases de prueba).

No es un defecto del codigo fuente: la compilacion (./gradlew build) y la
ejecucion (./gradlew bootRun) no se ven afectadas. Al clonar el repositorio en
una ruta ASCII (por ejemplo D:\dev\parqueadero), ./gradlew test pasa sin cambios.

Comandos ejecutados:
  backend             > ./gradlew test   -> BUILD SUCCESSFUL in 5m 35s
  auditoria-consumer  > ./gradlew test   -> BUILD SUCCESSFUL in 42s
  frontend            > npm run lint     -> exit 0
  frontend            > npm run build    -> exit 0
